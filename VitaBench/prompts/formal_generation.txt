### 🚨 CRITICAL: How to Handle Different Constraint Types

**1. Numerical Constraints → USE Dafny's Logic Power:**
```dafny
// GOOD: Let Dafny verify mathematical relationships
predicate PriceWithinBudget(s: AgentState) {{
  s.price <= s.budget  // Dafny verifies: 180 <= 200 ✓
}}

  s.quantity > 0 && s.quantity <= s.max_quantity
}}

  s.delivery_time <= s.user_deadline
}}
```

**2. Semantic Constraints → Extract STRUCTURED FEATURES, let Dafny COMPARE:**

❌ **WRONG** - Rigid string comparison:
```dafny
// BAD: Raw string comparison is not robust!
predicate VenueValid(s: AgentState) {{
  s.user_venue == s.agent_venue  // Not robust for variations
}}
```

❌ **ALSO WRONG** - Direct boolean without structure:
```dafny
// BAD: LLM just writes true/false, no Dafny logic involved

```

✅ **CORRECT** - Extract structured semantic features, let Dafny compare:
```dafny
// GOOD: Define structured semantic features
datatype VenueInfo = VenueInfo(
  city: string,               // "CityA"
  venue_category: VenueType,  // Sports | Olympic | Concert | Restaurant
  is_international: bool,     // false | true
  name_keyword: string        // "sports_center" | "olympic_center"
)

datatype AgentState = AgentState(
  user_venue: VenueInfo,    // What user specified
  agent_venue: VenueInfo    // What agent actually used
)

// Dafny compares the FEATURES - this is where the logic power is!
predicate VenueMatchesUserIntent(s: AgentState) {{
  s.user_venue.city == s.agent_venue.city &&                  // Same city?
  s.user_venue.venue_category == s.agent_venue.venue_category // Same category?
  // Sports != Olympic → FALSE → Dafny BLOCK!
}}
```

**Why this is better:**
- LLM extracts **semantic features** (city, category, type)
- Dafny **compares features** logically
- Transparent: you can see WHICH feature doesn't match
- Auditable: "Failed because venue_category Sports != Olympic"

**3. ID/Provenance Constraints → Extract IDs and use Dafny sets:**

### Code Structure Requirements:

```dafny

datatype ActionType = Query | Book | Cancel | Modify | Confirm

datatype VenueInfo = VenueInfo(

  action_type: ActionType,

datatype AgentState = AgentState(

  price: int,
  budget: int,
  quantity: int,
  max_quantity: int,
  delivery_time: int,
  deadline: int,
  
  // Structured semantic features - LLM extracts, Dafny compares
  user_venue: VenueInfo,     // What user specified
  agent_venue: VenueInfo,    // What agent used in tool call
  claimed_action: ActionInfo, // What agent said in explanation
  actual_action: ActionInfo,  // What agent did in tool call
  
  // Provenance - IDs and sources
  used_id: string,
  valid_ids: set<string>
)

// 4. CurrentState - LLM extracts features from conversation
function CurrentState(): AgentState
{{
  AgentState(
    // Numerical - extract actual values
    price := 180,
    budget := 200,
    quantity := 2,
    max_quantity := 5,
    delivery_time := 1130,
    deadline := 1200,

      venue_category := Sports,       // User said "Sports Center"

      is_international := false

      action_type := Query,

    ),
    actual_action := ActionInfo(
      action_type := Query,
      target_entity := "olympic_center",  // Agent DID Olympic Center
      claimed_entity := "CityA Olympic Sports Center"
    ),
    
    // Provenance
    used_id := "RESOURCE_ID_EXAMPLE",
    valid_ids := {{"RESOURCE_ID_EXAMPLE", "56"}}
  )
}}

// 5. Layer predicates - Dafny COMPARES the features
predicate Layer0_FormatValid(s: AgentState) {{
  s.used_id != "" &&
  s.price >= 0
}}

predicate Layer1_ConsistencyValid(s: AgentState) {{
  // Agent's claim must match agent's action
  s.claimed_action.target_entity == s.actual_action.target_entity

  s.quantity <= s.max_quantity &&                           // Numerical

predicate Layer5_TimeConstraintValid(s: AgentState) {{

predicate AgentActionIsSafe(s: AgentState)

  Layer1_ConsistencyValid(s) &&
  Layer2_UserConstraintsSatisfied(s) &&
  Layer4_ProvenanceValid(s) &&
  Layer5_TimeConstraintValid(s)

// 7. Main verification method
method VerifyAgentAction()
```

**Key Principle**: 
- **Numerical**: Extract values → Dafny does math (`180 <= 200`)
- **Semantic**: Extract structured features → Dafny compares features (`Sports != Olympic`)
- **Provenance**: Extract IDs → Dafny does set operations (`id in valid_set`)


### ⚠️ CRITICAL: ASSERTION DIRECTION (READ THIS CAREFULLY!)

**How the verification system works:**
1. You generate `assert AgentActionIsSafe(state);` (ALWAYS positive)
2. If the action violates constraints → `AgentActionIsSafe` evaluates to FALSE → Dafny **BLOCKS** → We detect the problem ✓
3. If the action is safe → `AgentActionIsSafe` evaluates to TRUE → Dafny **PASSES** → Action allowed ✓

**⛔ NEVER DO THIS:**
```dafny
// WRONG! This defeats the purpose of verification!
assert !AgentActionIsSafe(state);  // ❌ NEVER use negation!
assert !Layer1_ConsistencyValid(state);  // ❌ NEVER!
```

**✅ ALWAYS DO THIS:**
```dafny
// CORRECT! Let violations cause Dafny to BLOCK
assert AgentActionIsSafe(state);  // ✅ Always positive assertion
```

**Why?** The verification system interprets:
- Dafny PASS = Action is verified as SAFE
- Dafny BLOCK = Action VIOLATES constraints (we want this for bad actions!)

### Code Generation Guidelines:

1. **Only generate predicates for RELEVANT layers**
   - If Layer X is "Relevant: NO" in analysis, skip its predicate
   - Focus on layers with actual constraints

2. **Use strict mathematical logic**
   - Hard constraints (explicit user values): `assert price <= 200`
   - Soft constraints (semantic tags): `assert price <= inferred_max * 1.2`
   - Derived values (from tools): `assert IsValidFormat(id)` (trust the value)

3. **Distinguish tool types**:
   - READ tools (get_*, query_*): Minimal checks
   - EXPLORE tools (search_*, list_*): Allow incomplete info
   - WRITE tools (book_*, create_*): Require confirmation + complete info

4. **Handle time constraints correctly**:
   - Consider delivery/service duration
   - Allow reasonable buffers (20-30 min)
   - Check arrival time, not just dispatch time

5. **Trust tool-derived values**:
   - IDs from search results: Check format, not semantics
   - Prices from tool outputs: Trust the source
   - Focus on provenance, not perfect semantic match

6. **Avoid over-blocking**:
   - Don't block exploration/search actions for MISSING information
   - Don't require perfect information for read-only ops
   - Don't enforce abstract "phases"
   - **BUT: Still validate that provided parameters match user's requirements!**

7. **CRITICAL: Dafny String Handling**:
   - In Dafny, `string` is `seq<char>`, NOT a primitive type
   - **NEVER use `"substring" in str`** - this is a TYPE ERROR
   - For exact match: use `str == "value"`
   - For membership in sequence: use `"value" in seq_of_strings` (where seq is `seq<string>`)
   - For membership in set: use `"value" in set_of_strings` (where set is `set<string>`)
   - **If you need substring check**, define a helper function:
     ```dafny
     predicate ContainsSubstring(haystack: string, needle: string)
     {{
       |needle| <= |haystack| &&
       exists i :: 0 <= i <= |haystack| - |needle| &&
                   haystack[i..i+|needle|] == needle
     }}
     ```
   - **For keywords/tags checking**, prefer exact equality:
     ```dafny
     // WRONG: "outdoor" in keywords[i]  // TYPE ERROR!
     // RIGHT: exists i :: 0 <= i < |keywords| && keywords[i] == "outdoor"
     ```

8. **🚨 CRITICAL: Use STRUCTURED SEMANTIC FEATURES, not raw booleans:**
   
   **Numerical constraints → Let Dafny verify:**
